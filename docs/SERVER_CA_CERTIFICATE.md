# Server CA certificate

The ESP32 needs the server CA's **public certificate**, not the CA private key.
For the standard TrueNAS internal-Caddy deployment, the source file is:

`/mnt/Apps/Power/power-monitor/caddy-data/caddy/pki/authorities/local/root.crt`

Never copy, download, paste, or expose `root.key`. That file is Caddy's private
CA signing key and stays on the TrueNAS Caddy dataset.

## Get the public certificate

Choose one trusted method:

1. Export `root.crt` through a temporary administrator-only share, verify its
   SHA-256 fingerprint through an independent administrator channel, then remove
   the share.
2. From a client that already trusts the Power Monitor connection, download
   `https://power-monitor.local:8443/power-monitor-ca.crt`.

An unauthenticated TLS download cannot establish initial trust. Do not click
through certificate warnings or disable certificate verification.

On Windows, normalize and validate an exported certificate with:

```powershell
.\tools\prepare_server_ca.ps1 -CertificatePath C:\secure-transfer\root.crt
```

The helper rejects private-key files, verifies that the certificate has the CA
basic constraint, saves a predictable
`%USERPROFILE%\PowerMonitorTLS\power-monitor-server-ca.pem`, and prints its
SHA-256 fingerprint. It never reads or writes a private key.

## Provision the sensor

Open the sensor's first-run interface and:

1. Enter the stable HTTPS server URL, including port, for example
   `https://power-monitor.local:8443`.
2. Paste the complete contents of `power-monitor-server-ca.pem` into **Server CA
   certificate (public PEM)**.
3. Enter the single-use enrollment token generated by the server.
4. Submit setup and run the DNS, NTP, TLS, and heartbeat checks.

The hostname in the URL must be covered by the certificate. The firmware passes
the CA PEM to `WiFiClientSecure::setCACert` and verifies both the chain and
hostname for enrollment, signed heartbeats, backfill, configuration, and
firmware requests.
